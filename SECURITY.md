# Security Policy

Poseidon Labs is a public defensive-security and educational repository. Security reports are welcome, but public reporting must not expose people, credentials or live systems.

## Reporting a vulnerability in Poseidon Labs code

If GitHub private vulnerability reporting is available for this repository, use it for security-sensitive findings.

If it is not available, open a public issue containing only a minimal, non-sensitive description and ask for private coordination. Do not include exploit code, credentials, private logs, personal data or details that would expose a live system.

A useful report should include, when safe to share:

- affected project/file/version or commit
- the expected behaviour
- the observed behaviour
- security impact
- safe reproduction conditions using synthetic or local test data
- suggested mitigation, if known

## Out of scope

Do not use this repository as a channel to report vulnerabilities in unrelated third-party organisations, websites, networks or individuals.

Do not publish:

- stolen or leaked credentials
- secrets or recovery data
- private-system configuration
- identifying private network information
- instructions targeting a live system without authorisation

## Project boundary

Public examples should use synthetic, redacted or otherwise non-sensitive data. Project Poseidon keeps operational workstation hardening and private security records outside this public repository.

**Capability does not equal permission.**
